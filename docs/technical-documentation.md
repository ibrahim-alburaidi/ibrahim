# التوثيق الفني

## طبيعة التنفيذ

«بديل» ملف أعمال قائم على Markdown وJSON وأوامر جاهزة للاستخدام اليدوي مع نموذج لغوي. لا توجد خدمة خلفية أو API أو قاعدة بيانات أو نموذج مدرب داخل المشروع. Python مستخدم للفحص المحلي فقط، دون مكتبات خارجية أو اتصال شبكة.

## تدفق المعالجة

المستخدم يزود المصادر المرقمة → أمر استخراج → فحص اختلافات وفجوات → مراجعة المصدر والتصحيح → ملف تسليم ورسالة وخطة → اعتماد بشري → تحديث عودة عند توفر بيانات جديدة. المرجع الحالي أعده المساعد أثناء إنشاء المشروع؛ لا يوجد محرك استخراج تلقائي ضمن السكربت.

## المدخلات

[raw-input.md](../examples/raw-input.md) نسخة مقروءة، و[sources.json](../examples/sources.json) نسخة منظمة لنفس المحتوى. لا توجد أولوية لإحداهما عند الاختلاف؛ يجب تصحيح عدم الاتساق أولًا. الحقول:

| الحقل | النوع | المعنى |
|---|---|---|
| id | string | معرف ثابت وفريد: M01–M15 أو N01 |
| timestamp | string | وقت افتراضي بصيغة YYYY-MM-DD HH:MM |
| timezone | string | Asia/Riyadh، منفصل عن الوقت المحلي |
| role | string | الدور أو الاسم الافتراضي للمرسل |
| text | string | نص المصدر دون تعليمات تشغيل للمشروع |

## مخرجات المهام

الملف [tasks.json](../outputs/tasks.json) مصفوفة مهام. [handover.md](../outputs/handover.md) عرض بشري لنفس الحقائق الأساسية.

| الحقل | النوع | القاعدة |
|---|---|---|
| id | string | T01–T08 في العينة الحالية؛ فريد |
| task | string | إجراء المتابعة |
| owner | string أو null | شخص مثبت؛ null عند غيابه |
| due_date | string أو null | YYYY-MM-DD للموعد الواحد الصريح فقط |
| due_text | string | النص النسبي أو الموعد أو الموعدان المتعارضان |
| status | string | الحالة المدعومة، دون افتراض إنجاز |
| sources | array[string] | معرفات موجودة في المصادر؛ قائمة غير فارغة |
| dependency | string أو null | الاعتماد المذكور؛ null إن لم يُذكر |
| priority | string | مقترح تحليلي: عالية أو تحتاج تقييمًا في العينة |
| priority_reason | string | سبب الاقتراح؛ ليس تصنيفًا معتمدًا من الجهة |

بيانات التدريب المنظمة في [project-metadata.json](project-metadata.json) تتطابق مع الجدول في README وملف التدريب. يوضح [دليل الحقول](../outputs/evidence-map.md) إسناد المسؤول والمواعيد والحالات.

## قواعد القرار

1. فصل الحقيقة عن التوصية وعدم تحويل «بديلة معتمدة» إلى «مسؤولة عن كل المهام».
2. دمج المصدر المكمل دون محو التعارض: M05 يحدد المهمة والموعد، M13 يحدد المسؤول.
3. حفظ الموعدين المختلفين لـORD-021 وترك due_date=null؛ تأخر رسالة لا يكفي لإثبات اعتمادها.
4. الموعد النسبي في T06 يبقى في due_text ولا يتحول إلى ساعة أو تاريخ نهائي مفترض.
5. لا يعني وجود فاتورة لدى جهة أنها صرفت أو أن تلك الجهة مسؤولة عن الاستفسار.
6. الاعتماد الفرعي «بيانات نور» ضمن T05 لتجنب ازدواج العد في هذه العينة.
7. لا يُستنتج الإنجاز من انقضاء موعد ولا من غياب رسالة جديدة.
8. لا يُحسب مؤشر جهوزية رقمي؛ قد يخفي نقصًا حرجًا خلف متوسط مرتفع.

## ضمان الجودة وحدوده

[validate_project.py](../scripts/validate_project.py) يفحص الأقسام المطلوبة، JSON، فرادة المعرفات، تطابق نصوص المصدر بين النسختين، وجود روابط الملفات ومراسي المصادر، المراجع، واتساق الحقول الحرجة في العينة. يخرج برمز 0 عند النجاح و1 عند فشل فحص. لا يتصل بأي خدمة ولا يتحقق من صحة الروابط الخارجية.

أضيف فحص تطابق بيانات التدريب بين JSON وREADME وملف التدريب، وأنواع حقول المهام والمواعيد المعروفة وجدول الأولويات ومدة العرض. حالة الإذن بالنشر في هذه النسخة approved، بناءً على موافقة المستخدم الصريحة؛ هذه الحالة لا تثبت اعتمادًا أكاديميًا أو إنجاز مهام السيناريو.

يمكن تشغيل اختبارات الانحدار باستخدام `python scripts/test_validation.py`. تنشئ نسخًا مؤقتة، وتتحقق من قبول المشروع السليم ورفض خمسة تغييرات خاطئة: موعد معلوم في نسختي الناتج، اسم مخالف في الجدول، حقل نصي رقمي، مصدر غير موجود، ومدة عرض غير متسقة. لا تغيّر ملفات المشروع الأصلية.

الاختبارات الخاصة بالسيناريو تكشف أخطاء مثل ملء المسؤول المجهول أو حسم موعد الطلب، لكنها لا تتحقق دلاليًا من كل نص أو من أي مخرج نموذج جديد. [قائمة التحقق البشرية](../05-verification/verification-checklist.md) تكمل الفحص.
