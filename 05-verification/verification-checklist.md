# التحقق: Identify → Set Criteria → Test → Confirm and Decide

## القائمة الشخصية

1. أحدد المستند والغرض والمستلم.
2. أطابق الأشخاص والأرقام والمعرفات والتواريخ مع المصدر.
3. أتحقق من عدم اختلاق مسؤول أو موعد أو حالة أو تكلفة.
4. أفصل المقترح والاعتماد المعلق عن القرار المؤكد.
5. أراجع كل مصدر مختلف ولا أختار الأحدث تلقائيًا.
6. أحافظ على الاعتماديات والفجوات ولا أسقط بندًا مهمًا.
7. أراجع اللغة ووضوح المطلوب وعدم تحميل البديل مسؤوليات غير مثبتة.
8. أفحص الخصوصية والسرية والصلاحيات.
9. أسجل التصحيحات وحكم المراجع وتاريخه، وأترك اعتماد الإنسان معلقًا حتى يراجعه بالفعل.

## تطبيق عملي على T04 — تعارض موعد الطلب

| المرحلة | التطبيق |
|---|---|
| Identify | الادعاء المراد التحقق منه: «الموعد المؤكد 7 أكتوبر» |
| Set Criteria | لا قبول لموعد موحد مع وجود اختلاف، إلا بمرجع واضح لاعتماد أحد الموعدين |
| Test | M06 = 6 أكتوبر؛ M07 = 7 أكتوبر دون اعتماد تغيير؛ N01 يطلب الحسم |
| Confirm and Decide | رفض وصف 7 أكتوبر بالمؤكد؛ إظهار الموعدين، due_date=null، وطلب الحسم |

[مصادر التطبيق](../examples/raw-input.md).

## تطبيق عملي على ملف التسليم

| الفحص | ما وجد في المرجع المنقح | القرار |
|---|---|---|
| اكتمال المهام الرئيسية | 8 مهام مع مراجع؛ بيانات نور اعتماد داخل التقرير | متسق مع نطاق المثال |
| مسؤول الفاتورة | غير محدد بدل إسناده تلقائيًا للمالية | حفظ عدم اليقين |
| حالة التذكرة | أُعيد فتحها | متسقة مع M11 |
| الأولويات | موسومة بأنها مقترحات مع أسباب | تحتاج قرارًا بشريًا بحسب الأثر |
| سرية البيانات | المثال افتراضي ولا يحتوي كلمات مرور | مناسب للعرض التدريبي |
| اعتماد الإنسان | معلق في كل موضع | لا يجوز تحويله إلى معتمد آليًا |

هذه مراجعة أعدها المساعد؛ سجل المتدرب منفصل في [review-log.md](review-log.md). يفحص السكربت سلامة البنية والمراجع وبعض الحقائق الحاسمة، لكنه لا يصادق على صحة كل عبارة عربية أو ملاءمة القرار.
